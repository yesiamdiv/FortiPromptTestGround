# Instructions: `src/core/`

This directory is the **immutable backbone** of FotiPrompt. It defines the rules
every other part of the system must follow. Changes here affect everything.
Treat it with care — most features should be built *around* this, not *inside* it.

---

## The Three Files and Their Roles

### `state.py` — The Shared Clipboard
Defines `ArenaState`, a `TypedDict` that is the **only** object passed between nodes.

- All fields use `total=False` so nodes can return partial dicts. LangGraph merges them.
- If you need to carry new data between nodes, **add a field here first** before writing any node logic.
- Never create a second state object or pass data via any other mechanism.
- Field naming convention: `snake_case`, descriptive, no abbreviations.

Current fields and who owns them:

| Field | Written by | Read by |
|---|---|---|
| `run_id`, `goal`, `strategy`, `max_turns` | Orchestrator seed | Anyone |
| `turn_count` | Orchestrator attacker wrapper | Router, telemetry |
| `chat_history` | Orchestrator both wrappers | Attacker strategies |
| `current_prompt` | Attacker node | Defender node, Judge node |
| `current_response` | Defender node | Judge node |
| `evaluation_result` | Judge node | Router |
| `evaluation_reasoning` | Judge node | Telemetry |
| `strategy_metadata` | Attacker internal scratchpad | Attacker only |
| `final_outcome` | Telemetry node | Caller in main.py |

### `interfaces.py` — The Contracts
Defines the four abstract base classes every plugin must implement:

- `BaseAttacker` — must implement `generate_attack(state) -> dict`
- `BaseDefender` — must implement `get_response(state) -> dict`
- `BaseEvaluator` — must implement `evaluate(state) -> dict`
- `BaseAttackStrategy` — must implement `build_prompt(state) -> str` and `should_reset_history(state) -> bool`

All four have optional `setup(**kwargs)` and `teardown()` hooks the Orchestrator calls before and after the graph runs.

Do not add business logic here. These are pure contracts. If you find yourself writing an `if` statement in this file, it belongs in a concrete implementation instead.

### `orchestrator.py` — The Graph Engine
Builds and runs the LangGraph state machine. Contains:

- Four private node factory functions that each wrap a plugin and handle cross-cutting concerns the plugin should not know about: turn incrementing, history appending.
- `_route_after_judge()` — the conditional edge function. The **only** place routing logic lives.
- `Orchestrator` class — the public API. Accepts plugin instances, builds the graph lazily on first `run()` call.

---

## What the Orchestrator Does vs Does NOT Do

| Does | Does NOT do |
|---|---|
| Defines node execution order | Know what any node does internally |
| Appends to `chat_history` after each node | Summarise or modify history content |
| Increments `turn_count` | Track strategy state |
| Calls `setup()` and `teardown()` on plugins | Manage LLM connections |
| Routes based on `evaluation_result` | Interpret what "breached" means |
| Seeds the initial `ArenaState` | Know what model any node uses |

---

## Routing Logic — Do Not Change Without Care

The router `_route_after_judge()` has exactly three branches:

```
evaluation_result == "breached"             → "telemetry"   end, attacker won
evaluation_result == "blocked" + max turns  → "telemetry"   end, defender won
evaluation_result == "blocked" + turns left → "attacker"    loop continues
```

`evaluation_result` must always be exactly `"breached"` or `"blocked"` in lowercase.
Any other value silently falls through to the blocked branch. Evaluator modules are
responsible for guaranteeing this output format.

## What Still Needs to Be Done in This Directory

- [ ] **`state.py`** — Add a `run_config: dict` field for arbitrary per-run settings. Lets callers pass custom parameters to specific plugins without adding top-level fields every time.

- [ ] **`orchestrator.py`** — `final_outcome` can currently be `"ongoing"` if a mid-run state snapshot is taken. The returned state from `run()` should never be `"ongoing"`. Add a finalisation step that resolves it to `"attacker_wins"` or `"defender_wins"` before returning.

- [ ] **`orchestrator.py`** — `setup()` is called on every `run()` invocation. In batch mode this means setup runs on every single test case. Either guard with a flag or document that `setup()` must be idempotent.

- [ ] **`orchestrator.py`** — No error handling around node execution. If any node raises mid-run, the graph crashes and nothing gets logged to telemetry. Wrap node factories in try/except, write an error state, then re-raise so the caller knows what happened.

- [ ] **`interfaces.py`** — `BaseAttackStrategy` is only used by `LLMAttacker`. Evaluate whether it belongs here in `src/core/` or should move to `src/attackers/` since nothing else in core references it.
